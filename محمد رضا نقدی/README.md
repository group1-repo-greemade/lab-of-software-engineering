# سامانه احراز هویت — محمدرضا نقدی

یک برنامه وب مبتنی بر Python، Flask و SQLite برای ثبت‌نام، ورود، مدیریت نشست و نمایش داشبورد خصوصی کاربر.

## امکانات
- ثبت‌نام با نام کاربری ۳ تا ۲۰ کاراکتری (حروف انگلیسی، عدد و زیرخط).
- رمز عبور با طول ۸ تا ۱۲۸ کاراکتر و ذخیره‌سازی به‌صورت hash.
- ورود با پیام خطای یکسان برای نام کاربری ناموجود و رمز عبور نادرست.
- جلوگیری از نام کاربری تکراری بدون حساسیت به بزرگی/کوچکی حروف.
- محافظت از همه درخواست‌های POST با CSRF token.
- نشست احراز هویت با نگهداری user_id؛ رمز عبور خام در نشست ذخیره نمی‌شود.
- داشبورد محافظت‌شده با اطلاعات پایه حساب و تعداد کاربران.
- بستن نشست هنگام خروج یا شناسایی نشست نامعتبر/حساب حذف‌شده.
- هدرهای امنیتی و امکان تزریق تنظیمات جداگانه برای تست‌ها.

## معماری
| فایل | مسئولیت |
|---|---|
| app.py | ساخت Flask app، routeها، نشست، CSRF و پاسخ‌های HTTP |
| auth_service.py | اعتبارسنجی ثبت‌نام و بررسی اطلاعات ورود؛ مستقل از Flask و SQL |
| repository.py | دسترسی به کاربران و اجرای queryهای SQL |
| database.py | چرخه عمر اتصال SQLite و ایجاد schema |
| schema.sql | تعریف جدول users و محدودیت‌های آن |
| config.py | مسیر دیتابیس، کلید نشست و تنظیمات امنیتی |
| templates/ | فرم ورود/ثبت‌نام و داشبورد کاربر |
| tests/test_auth.py | تست جریان‌های اصلی، نشست، CSRF و هدرهای امنیتی |

## مسیرهای HTTP
| Method | Path | دسترسی | توضیح |
|---|---|---|---|
| GET | / | عمومی | هدایت به ورود یا داشبورد |
| GET / POST | /signup | مهمان | نمایش فرم و ایجاد حساب |
| GET / POST | /login | مهمان | نمایش فرم و احراز هویت |
| GET | /home | کاربر واردشده | مشاهده داشبورد خصوصی |
| POST | /logout | نشست فعال | پاک‌کردن نشست |

## مدل داده
جدول users شامل id (کلید اصلی)، username (یکتا و بدون حساسیت به حروف)، password_hash و created_at (زمان UTC) است.

## اجرای محلی
1. ساخت محیط: python -m venv .venv
2. فعال‌سازی در Linux/macOS: source .venv/bin/activate
3. نصب: pip install -r requirements.txt
4. اجرا: python app.py
5. بازکردن: http://127.0.0.1:5000

برای محیط تولید از WSGI server و HTTPS استفاده کنید و SESSION_COOKIE_SECURE را فعال کنید.

## تست
دستور اجرا: pytest -q
تست‌ها از دیتابیس موقت استفاده می‌کنند و به دیتابیس محلی برنامه دست نمی‌زنند.

## هفت نمودار UML
فایل UML-project-weak9/Authentication_System_7_UML.drawio شامل هفت نمودار هماهنگ با پیاده‌سازی است:
1. Use Case — نقش مهمان و کاربر واردشده و قابلیت‌های سیستم.
2. Class — مدل User، نتیجه احراز هویت و مسئولیت لایه‌های برنامه.
3. Sequence — توالی پیام‌ها در ورود موفق/ناموفق.
4. Activity — جریان کنترل درخواست ورود و تصمیم‌های امنیتی.
5. State Machine — چرخه عمر نشست ناشناس و احراز هویت‌شده.
6. Component — وابستگی رابط وب، routeها، سرویس، repository و دیتابیس.
7. Deployment — مرورگر، فرایند Flask و فایل‌های محلی SQLite/کلید نشست.

جزئیات توصیه‌شده برای محیط تولید در یادداشت Deployment از استقرار فعلی محلی جدا شده‌اند.
